# Minimum Value to Get Positive Step by Step Sum.

@example With 3 the balances are 7, 1, 4, 2 and 7; with 2 the second one would be 0.
[4,-6,3,-2,5]
=> 3

@example Nothing is ever taken out, and v can't be less than 1.
[2,5,1]
=> 1

@example Three withdrawals take out 6 before the 9 comes in, so 7 is needed, though the last balance would be positive from any start.
[-2,-2,-2,9]
=> 7

# A single deposit, or a single transaction of 0.
[5]
=> 1

[0]
=> 1

# A single withdrawal, as small and as large as allowed.
[-1]
=> 2

[-100]
=> 101

# The balance falls back to v exactly, never below it: 1 is enough.
[3,-3,2,-2]
=> 1

# The balance never falls below v + 1. A start of 0 would just do, but v
# can't be less than 1.
[1,3,-3,4]
=> 1

# The balance dips to 1 below v, twice: the totals must reach 1,
# not 0, so 2 is needed.
[2,-3,5,-5]
=> 2

# The lowest balance comes right after the first transaction.
[-5,1,1,1]
=> 6

# The lowest balance comes after the last transaction.
[1,1,1,-8]
=> 6

# Several withdrawals in a row go deeper than any one of them, and the
# final balance is high.
[5,-4,-4,-4,30]
=> 8

# Deep in the middle, then back above the start.
[-50,-50,100,100]
=> 101

# The running total climbs to 200 before falling to -50; a signed char
# can't hold 200 (it would wrap to -56, below the real lowest total).
[100,100,-100,-100,-50]
=> 51
